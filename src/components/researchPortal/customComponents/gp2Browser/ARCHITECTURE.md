# GP2 Browser — architecture

Technical overview of **GP2 Browser** in dig-dug-portal. For UI conventions, see [`DESIGN.md`](./DESIGN.md). For agent workflow and pitfalls, see [`AGENTS.md`](./AGENTS.md).

## Shared implementation

GP2 Browser is a thin shell (`../GP2Browser.vue`) that **reuses the KP Variant Sifter component and module tree** under [`../kpVariantSifter/`](../kpVariantSifter/).

This folder keeps GP2-specific notes only. Do not duplicate identical runtime files here.

When a GP2 change touches any module or component shared with KP Variant Sifter or another project, create a new GP2-only file (named `GP2Browser*` / `gp2Browser*`) under `gp2Browser/` and import it from `GP2Browser.vue`; leave the shared file in `kpVariantSifter/` untouched.

For system structure, session model, data flow, and assistant runtime, see [`../kpVariantSifter/ARCHITECTURE.md`](../kpVariantSifter/ARCHITECTURE.md).

## GP2 data-loading & rendering architecture

1. **Settings-driven on-demand data loading (`GP2Browser.vue`)**:
   - Default checked sections on startup: `associations`, `qtl-evidences`, `genes`. Checking `qtl-evidences` does **not** itself trigger a QTL fetch (see QTL loading below).
   - `loadInitialSearchData`, `loadDataForCheckedSections` (section newly checked), and additive phenotype/ancestry loaders only query BioIndex for sections currently checked in `visibleSectionIds`. QTL evidences is excluded from both of these, skipping the initial/checked-section load entirely (see QTL loading below) — but unlike Gene links / SNP 2 gene links, it *does* react to `syncRegionDataToView` region extension (zoom-out/pan widening the searching region): `finishRegionExtendSync()` calls `maybeLoadQtlEvidences()` on every region-sync pass, so an active type+tissue selection's QTL data catches up to the newly widened region. Since QTL fetches the whole region in one BioIndex call (not per-ancestry gap-by-gap like Associations), this is a plain whole-region refetch rather than incremental gap-filling.
   - Per-section loaded region trackers (`lastAssociationsRegion`, `lastGenesRegion`, `lastQtlRegion`, `lastCredibleSetsListRegion`, `lastGlobalEnrichmentRegion`, `lastV2gCatalogRegion`, `lastS2gRegion`) record which genomic region each feature has loaded.
   - When a user checks a previously unchecked section in Settings (`onVisibleSectionIdsUpdate` → `loadDataForCheckedSections`), `GP2Browser.vue` immediately fetches the missing data for the active locus region (except QTL — see below).
   - **QTL loading is gated on drawer selection, not region/section checks:** `maybeLoadQtlEvidences()` only calls `loadQtlEvidencesForSession` when at least one type and one tissue are checked in `qtlState.selectedTypes`/`selectedTissues` AND the current searching region isn't already loaded or loading (`lastQtlRegion`). It's invoked from `onQtlSelectedTypesUpdate`/`onQtlSelectedTissuesUpdate` (the normal path — checking a box), from `onStartSearch` (covers a new search where a prior selection persisted across `emptyQtlState`), from `onVisibleSectionIdsUpdate` when `qtl-evidences` is newly checked (covers re-checking the section with a selection already made), and from `finishRegionExtendSync` (covers the searching region widening via zoom-out/pan after a selection is already active). This intentionally does not scale network calls with the number of type/tissue options the way preloading would.
   - `qtlState` holds both `rawRows` (the true, undownsampled `qtl-associations` response for the whole searching region) and `downsampledRows` (a stable snapshot computed once via `downsampleAssociationRowsOnLoad` right after fetch, in `loadQtlEvidencesForSession`) — both unfiltered by type/tissue/p-value. The QTL drawer table and the searching-region plot filter `downsampledRows` client-side (type/tissue via `filterQtlRows`, p-value via `filterQtlRowsByPValueMax`); the 50 kb viewing-region plot filters `rawRows` the same way plus a 50 kb-region restriction (`restrictQtlRowsToRegion`), so it shows raw (not downsampled) data like the Associations viewing plot does. Toggling a type/tissue checkbox, editing the p-value filter, or opening/closing the drawer never triggers a network call. The **QTL evidences** plot section (`showQtlEvidencesSection` in `GP2BrowserAssociationsPlot.vue`) stays hidden entirely (no header, no placeholder) until `qtlHasSelection` is true.
   - **Drawer tables show the downsampled searching region, plus pinned starred rows:** The Associations drawer table (`associationsDrawerRows` in `GP2BrowserSectionDrawers.vue`) and the big data-table modal's Associations tab (`associationTableRows` in `GP2BrowserCanvas.vue`) both strip any `_zoomRefetched` rows from `associationsState.rows` first (`stripZoomRefetchedRows`), so they always show the stable 0%-zoom downsampled baseline across the whole searching region rather than whatever dense raw data a 100%-zoom refetch temporarily merged in. The QTL drawer table does the analogous thing by reading `qtlState.downsampledRows` instead of `rawRows`. In both cases, any variant the user has starred (from a plot dot or the table's star column) that would otherwise be missing from that baseline is added back in — `addMissingStarredAssociationRows` / `addMissingStarredQtlRows` — using the full row captured inside the star entry itself (`createStarredVariant`/`toggleStarredVariant` in `variantSifterPlotMarkers.js` store `row: {...row}`), bypassing type/tissue/p-value filtering since starring is an explicit user pin.

2. **Load-time association downsampling & 100% zoom refetch (`gp2BrowserAssociationsDownsample.js`, `variantSifterAssociationsApi.js`, & `GP2Browser.vue`)**:
   - **0% zoom load-time filter**: `fetchAssociations` and `fetchGwasCeAssociations` run `downsampleAssociationRowsOnLoad` as soon as BioIndex pages complete, keeping 100% of variants with `p <= 0.05` and keeping `p > 0.05` variants when `Math.random() <= Math.pow(1 - p, 9)`. Filtered-out rows are immediately discarded so full raw locus arrays are never retained in memory.
   - **100% zoom snap (dormant)**: `regionZoom`/`regionZoomOut` can still reach `99`/non-zero internally (session restore, the AI Assistant's zoom action), but the "Region zoom" slider that used to let a user drag to `100%` from the toolbar was replaced by the **Zoom level:** dropdown (see Viewport controls above) — nothing in the remaining UI sets `regionZoom` away from `0` anymore.
   - **Optional zoomed-in region refetch (`refetchAssociationsOnZoom`, dormant)**: Controlled by **Settings → General → Region zoom → Refetch association data for zoomed-in region** (checked by default). When enabled and zoomed to `100%` (including after panning while zoomed in), `refetchAssociationsForZoomedView()` fetches un-downsampled (`{ downsample: false }`) association rows for `viewRegion`, copies cached LD scores from the 0%-zoom rows (`applyCachedLdScoresToRows`, without calling the LD server), and tags zoomed-only rows with `_zoomRefetched: true`. Returning to `0%` zoom (or unchecking the setting) strips `_zoomRefetched` rows (`stripZoomRefetchedRows`) to restore the 0%-zoom baseline. This path is intact but effectively unreachable now that nothing sets `regionZoom` to `99` via normal UI.
   - **Configurable viewing-region width**: `GP2Browser.vue`'s `viewingRegionWidthBp` (data, default `GP2_VIEWING_REGION_WIDTH_BP` = 50000) replaces the old fixed `±25 kb` constant as the actual viewing-region size. `viewingRegionHalfWidthBp` (computed, half of the width) is threaded as a prop through `GP2BrowserCanvas.vue` → `GP2BrowserAssociationsPlot.vue` → `GP2BrowserAssociationRegionPlot.vue` / `GP2BrowserQtlRegionPlot.vue`, and passed explicitly to every `computeGp2ViewingRegion`/`clampViewingCenterBp` call (replacing their default-parameter fallback to the fixed constant) so handle-dragging, keyboard-nudging, and viewing-plot panning all clamp against the currently selected width. `GP2BrowserViewportControls.vue`'s **Zoom level:** `<select>` emits `update:viewingRegionWidthBp`, handled by `onViewingRegionWidthUpdate` in `GP2Browser.vue`.
